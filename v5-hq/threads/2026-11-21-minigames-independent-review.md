# 놀이기구 미니게임 요청 독립 검증 준비 — 2026-11-21

- 요청: 거울미로를 유지하고 캡틴 훅의 기존 기능을 보존한다. 관람차는 별 잇기, 회전목마는 태엽, 찻잔은 바퀴를 거부할 때 키퍼가 개입하는 조작으로 교체한다. 거울미로 외 모든 기구에 미니게임 그래픽과 간결한 조작창을 적용한다. 세부 조작의 선택은 구현 및 사용자 결정에 따른다.
- 기존 연결: 관람차·회전목마·찻잔은 `story-core.js`의 `openRideGame()`과 `success()` 경로를 사용한다. 3D에서는 `story-3d.js`가 좌석 탑승·실제 기구 시작·완료 후 결과 반영을 감싼다. 도움·위험 및 재시도 상태, 키퍼 사건·관계 수치·클리어·출구·엔딩의 기존 연결이 끊기거나 중복 처리되지 않아야 한다.
- 유지 범위: 거울미로의 실제 내부 이동·출구와 기존 퍼즐/완료 처리 및 캡틴 훅 첫 승선 사고·재탑승 레버·왼쪽 조언과 강제 이동·취소가 회귀하지 않아야 한다. 롤러코스터의 기어·레버·주행도 기존 기능 유지와 그래픽 적용 범위에 포함되는지 실제 결과를 사용자 요청의 ‘거울미로 외 모든 기구’에 비추어 확인한다.
- 핵심 검증: 세 기구에서 요청한 실제 입력과 키퍼 개입이 올바른 조건에서 작동하고 성공·거부·취소·재진입 뒤 실제 탑승과 결과로 이어지는지, 중복 출발이나 예약 동작 누수가 없는지 확인한다. 찻잔 거부가 단순 실패/도움 선택과 혼동되지 않는지, 사용자 의도에 맞는 사건 순서를 확인한다.
- 그래픽 검증: 거울미로를 제외한 모든 실제 이용 가능 기구에서 새 조작 그래픽과 간결한 창이 표시되는지, 옛 이모지/슬라이더 화면이 요청을 대신하지 않는지, 작동 요소·안내·취소가 손·그림과 겹치지 않는지 데스크톱/작은 화면에서 살핀다. 터치·마우스·키보드, 읽을 수 있는 대비, 포커스, 상태 안내와 움직임 감소도 검증한다.
- 기존 테스트는 이전 퍼즐 방식 또는 모의 DOM을 가정할 수 있으므로 통과만으로 새 조작 및 실제 화면을 증명하지 않는다. 테스트 범위, 실제 브라우저·터치 미검증 사항을 구분한다. 사용자의 진행 중인 탭과 저장을 보존한다. 게임 코드는 수정하지 않았다.

## 구현본 독립 검토 — 2026-11-21
- `ride-interactions.js`는 관람차 1~5 순서 별 버튼, 회전목마 태엽, 찻잔 바퀴를 제공하고 거부·방치·역방향에서 키퍼 개입 후 `onStart({forced:true})`를 호출한다. `story-core.js`는 1·2·4를 공통 모듈에 연결해 `success(forced)`를 호출하며, 3은 기존 거울미로 경로를 유지한다. 이미지 원본 두 파일을 직접 확인했으며 게임의 초록·금색·유원지 화풍과 어울리는 세 장면과 태엽·바퀴 그림이 있다. 실제 화면 배치·터치·가독성은 검증하지 않았다.
- `node verify-ride-interactions.cjs`, `node verify-captain-lever.cjs`, `node verify-keeper-story.cjs`, `node verify-coaster-lever.cjs` 통과. 새 모듈 검사는 모의 DOM에서 각 직접·거부·방치, 회전 역방향, 파괴 시 타이머 정리 및 단일 콜백을 확인한다. 스토리 검사는 새 모듈을 로드하지 않고, 새 모듈 검사는 `success()` 및 실제 3D 탑승을 연결하지 않으므로 새 조작→스토리→탑승 통합은 독립 자동 검증되지 않았다.
- 발견: 새 세 기구 창에는 '멈추고 싶어요' 한 버튼만 있으며 이는 닫기가 아니라 `force()`로 키퍼 개입·출발을 시작한다. 기존 '데크로 돌아가기'에 해당하는 사용자 취소 경로는 모듈에서 확인되지 않는다. 테스트의 cancellation은 코드에서 `ui.destroy()`를 직접 호출하므로 플레이어가 취소할 수 있음을 증명하지 않는다. 이는 취소·닫기 회귀이며 의도 확인과 수정 필요.
- 롤러코스터는 검토 중 파일이 갱신돼 기어 생략 후 레버를 즉시 연다. 이전 `node threads/verify-coaster-integration.cjs`는 제거된 기어/트레이를 기대해 실패(트레이 hidden assertion)하므로 더 이상 최종 경로의 통과 근거가 아니다. 새 경로에서 직접·강제 출발, 취소·재입장·타이머 정리를 검증하는 갱신된 통합 검사 및 실제 화면 확인이 필요하다. 실패는 기존 테스트의 낡은 가정이며 곧바로 게임 오류를 뜻하지 않는다.
- 코드상 종료/모달 교체 시 `rideInteractionUI.destroy()`가 타이머를 지우지만 실제 닫기 UI, 스토리 결과와 3D 연결, 반응형 및 화면상 키퍼 손 접점은 미검증이다. 게임 구현 파일은 수정하지 않았다.

## HQ 확인 및 의도 정정 — 2026-11-21
- HQ는 사용자의 이번 의도가 거부해도 키퍼가 강제로 작동시키는 것이라고 확인했다. 앞선 ‘멈추고 싶어요’가 강제 개입으로 이어지는 점을 문제로 지적한 것은 요청 의도에 대한 잘못된 해석이므로 철회한다. 별도 퇴장/취소 기능의 필요 여부를 이번 요청의 결함으로 단정하지 않는다.
- HQ가 실제 게임에서 관람차 직접 완료→이야기 연결, 회전목마 역방향→이야기 연결, 찻잔 거부와 반사 손, 롤러코스터 기어 없이 레버 표시→출발을 확인했다고 전달했다. 이는 HQ의 실제 화면 검증이며 이 독립 스레드가 직접 관찰한 결과는 아니다.
- 갱신된 자동 검사가 준비되면 새 조작→스토리/실제 탑승과 롤러코스터 레버 직행, 타이머 정리를 재검증한다. 찻잔 거부 후 최종 탑승, 모바일 터치 등 위에 명시되지 않은 화면 검증은 완료로 추정하지 않는다.

## 갱신 테스트 독립 재실행 — 2026-11-21
- `node verify-coaster-entry.cjs`, `node verify-ride-interactions.cjs`, `node verify-coaster-lever.cjs`, `node verify-captain-lever.cjs`, `node verify-game-tools.cjs` 모두 종료 코드 0으로 통과했다. 새 롤러코스터 검사는 기어 없이 레버 즉시 열기, 취소 후 공원 복귀, 출발과 닫기 계약을 모형에서 확인한다. 레버 모듈 자체의 직접·강제 출발과 타이머 정리는 별도 단위 검사다. 이 진입 검사는 레버를 모의 객체로 대체하므로 실제 두 모듈 결합을 단독으로 증명하지 않는다.
- 오르골은 회전목마를 직접 감는 진행 중 Web Audio 음을 생성하고 음소거·볼륨 설정을 확인한다. 검사는 처음 열 때 무음, 수동 감기 시 음 발생, 음소거 시 음 없음, 키퍼 강제 개입 시 자동 재생 없음의 호출을 모형 AudioContext로 확인한다. 실제 소리의 음질·브라우저 재생과 모바일 환경은 이번에 듣지 않았다.
- 새 미니게임 단위 검사는 직접·거부·방치·역방향과 정리·중복 출발 방지를 모형에서 확인한다. 기존 스토리 검사는 새 모듈을 로드하지 않으므로 새 모듈→스토리→실제 탑승 자동 통합 검증으로 간주하지 않는다. HQ가 앞서 실제 화면에서 관람차 직접·회전목마 역방향의 이야기 연결, 찻잔 거부·반사 손, 롤러코스터 레버 직행과 출발을 확인했다고 전달했다.
- HQ가 확인한 바에 따라 거부 후 키퍼 강제 개입은 요청 의도다. 이번 검증에서 게임 구현 파일을 수정하지 않았다.

## 기구별 새 조작·손 이미지 검증 계획 — 2026-11-21
- 새 요청: 롤러코스터는 안전바를 아래로 당기며, 찻잔은 주전자를 아래로 당겨 따르는 조작으로 바꾼다. 관람차·회전목마·찻잔·롤러코스터의 키퍼 손은 각각 해당 동작에 맞는 별도 신규 이미지로 제작하고 캡틴 훅 기존 손은 유지한다.
- 현재 기준: 롤러코스터는 캡틴 훅과 같은 수평 레버를 사용하고 찻잔은 회전목마와 같은 회전 바퀴 구조다. 관람차·목마·찻잔은 동일한 캡틴 훅 손 PNG를 참조한다. 따라서 실제 사용 경로·이미지 연결을 확인해야 하며 원본 파일 생성만으로 완료로 판정하지 않는다.
- 통합 후 두 새 조작에서 마우스/터치 아래 방향과 키보드 대체 조작, 반대/거부/방치 시 요청된 개입, 직접 및 강제 출발과 기존 3D·이야기 결과, 취소·재입장·타이머 정리와 움직임 감소를 확인한다. 회전목마의 태엽·오르골, 관람차의 별 잇기, 거울미로, 캡틴 훅 기존 수평 레버와 손·이야기가 회귀하지 않아야 한다.
- 4개 신규 손 이미지가 각 놀이기구에 실제로 다르게 연결되고 손·손가락이 별, 태엽, 주전자, 안전바의 행동에 맞게 닿고 따라 움직이는지, 캡틴 훅 손은 변경되지 않았는지 원본·화면에서 확인한다. 초기·중간·끝, 작은 화면, 이미지 오류, 포커스·안내·접근성과 레이어 겹침을 확인한다.
- 새 조작→실제 이야기·탑승 연결은 단위 모형만으로 증명하지 않으며 실제 브라우저 확인과 테스트 범위를 구분한다. 사용자 진행 탭·저장을 보존한다. 구현 파일은 수정하지 않았다.

## 안전바·주전자·기구별 손 최종 독립 검증 — 2026-11-21
- `coaster.js`는 공통 수평 레버 대신 `NEVERLAND_COASTER_SAFETYBAR`를 열고, 안전바는 아래 입력으로 직접 출발하며 반대 방향·거부·방치에서 키퍼 개입으로 출발한다. 찻잔은 바퀴 대신 주전자 아래 당기기/차 따르기를 사용한다. 관람차 별, 회전목마 태엽과 오르골은 유지하고, 거울미로는 기존 경로, 캡틴 훅은 기존 수평 레버 및 `keeper-captain-lever-hand-v2.png` 경로를 유지한다.

- 순차 실행한 `node verify-coaster-safetybar.cjs`, `node verify-coaster-entry.cjs`, `node verify-ride-interactions.cjs`, `node verify-coaster-lever.cjs`, `node verify-captain-lever.cjs`, `node verify-keeper-story.cjs` 모두 종료 코드 0. 모의 DOM·타이머에서 안전바 직접/반대/거부/방치/취소/정리, 찻잔 직접 키·포인터/반대/거부/방치/정리, 별과 태엽, 캡틴 훅과 이야기 회귀를 확인한다. 안전바 진입 검사는 안전바 모듈을 모의하고 스토리 검사는 새 모듈을 로드하지 않으므로 실제 컴포넌트→이야기·3D 연결을 이 검사들만으로 확정하지 않는다.
