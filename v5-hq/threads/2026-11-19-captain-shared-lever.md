# 캡틴 훅 공통 레버 적용 (2026-11-19)

- 요청: 롤러코스터 레버는 유지하고 캡틴 훅 첫 승선 및 이후 맵 조작에서 같은 레버를 사용. 기존 안전 구간, 이야기, 키퍼의 역방향 개입 및 다른 놀이기구는 보존.
- 결과: 첫 승선에서 오른쪽 끝 또는 역방향 강제 이동으로 기존 출항 대사를 시작한다. 이후 캡틴 훅 조작은 같은 레버로 안전 눈금을 맞춰 기존 작동 확인·도움·재시도·위험 강행 판정을 사용한다. 안전 판정 후 같은 레버를 오른쪽 끝까지 당겨 기존 사건 대화와 실제 항해로 이어진다. 안전 조작 중 역방향이면 강제로 100으로 가며 기존 안전 판정에 따라 실패·도움 선택이 나타나고 레버가 다시 준비된다. 첫 승선 및 재조작 취소·화면 전환 시 예약된 출발을 정리한다.
- 변경: `neverland-v4/story-core.js`, `coaster-lever.js`, `keeper-story.js`, `verify-captain-lever.cjs`, `verify-full-story.cjs`. 공통 레버에는 선택적인 안전 조작 모드를 추가했으며 롤러코스터 호출은 기본 모드를 유지한다.
- 검증: `node verify-captain-lever.cjs` 실제 공유 모듈+첫 승선 및 안전 조작 경로 자동 검증 통과. 안전 구간 성공 후 기존 키퍼 선택과 항해, 강제 역방향 실패 후 도움·재시도·강행 표시 확인. `node verify-coaster-lever.cjs`, `node ../threads/verify-coaster-integration.cjs`, `node verify-keeper-story.cjs`, `node verify-game-tools.cjs` 통과. 기존 원본 코드 바이트 동일성 검사는 의도된 조작 변경으로 연결 검사로 교체. 모의 DOM 테스트이며 실제 브라우저 조작과 터치 화면 시각 검증은 별도 필요. 미리보기는 앱 브라우저 시작 화면에 열어둠.

## 기존 조작판 제거 및 단일 레버 보정
- HQ 브라우저 검토에 따라 공통 레버가 있을 때 첫 승선·재탑승 창에서 기존 `captainVisual` 배 그림, 상태판과 옛 레버를 생성하지 않는다. 표시 요소가 없어도 상태 갱신은 안전하게 빠져나가며, 3D 기구 동력 갱신은 유지한다. 모듈이 없는 기존 호환 경로는 원래 화면을 사용한다.
- 추가 지시에 따라 재탑승의 안전 구간 선행 단계와 두 번째 출발 레버를 제거했다. 하나의 공통 레버를 오른쪽 끝까지 당기거나 왼쪽으로 역조작하면 기존 키퍼 사건·선택지와 실제 항해로 이어진다. 이전 절의 안전 구간 재조작 설명은 더 이상 현재 상태가 아니다.
- 자동 검증: `verify-captain-lever.cjs`가 첫 승선·재탑승, 직접·강제 출발, 취소, 기존 화면 미생성, 시각 요소가 없는 상태의 갱신, 스토리 선택과 실제 항해까지 통과. 롤러코스터 단위·통합 검사, 키퍼 이야기 및 제작 도구 검사 통과.
- 브라우저에서 제작 장면 이동으로 첫 승선 화면을 열어 옛 조작판 없이 새 레버가 표시되는 것을 확인했다. 왼쪽 방향키 개입 후 기존 출발 대사로 전환되는 것도 확인했다. 재탑승 화면과 터치 실기기는 이번 브라우저 검사 범위 밖이다.

## 키퍼의 첫 역방향 안내 (2026-11-19)
- 공통 레버에서 각 조작 화면의 첫 왼쪽 시도에 “왼쪽이 아니라 오른쪽이에요. 천천히, 제가 도와드릴게요.”를 상태 안내로 표시한다. 3초 후 기존 키퍼 손 강제 이동과 출발이 이어진다. 안내는 장면 위에 표시하고 스크린리더 상태 안내도 사용한다.
- 포인터·터치·키보드가 같은 경로를 사용하며, 움직임 줄이기에서도 3초 읽기 시간은 유지하고 이후 움직임 없이 출발한다. 안내 중 반복 입력은 무시하고, 취소·화면 파괴 시 예약된 출발을 취소한다. 재입장하면 새 조작으로 안내가 다시 가능하다. 정상 오른쪽 출발은 지연되지 않는다.
- 변경: `neverland-v4/coaster-lever.js`, `neverland-v4/verify-coaster-lever.cjs`. 이미지 파일은 변경하지 않았다.
- 검증: 가상 시계로 2,999ms 동안 출발·레버 이동 없음, 3초 후 강제 출발, 키보드·포인터, 움직임 줄이기, 안내 중 취소·새 조작을 확인. 공통 레버 단위, 캡틴 훅 첫 승선·재탑승, 롤러코스터 기어→레버 통합 검사 통과. 실제 터치 기기 및 시각 확인은 별도 필요.

## 움직임 줄이기 손 표시 보정
- 움직임 줄이기 설정에서는 안내 3초 후 레버와 키퍼 손을 애니메이션 없이 오른쪽에 표시하고 1.2초 유지한 뒤 출발한다. 기존 손 이미지 기본 경로와 에셋은 변경하지 않았다.
- 가상 시계 검사에서 정지 손 표시 시점과 1.2초 대기, 대기 중 취소 시 출발 방지, 재입장 후 초기화와 재출발을 확인했다. 공통 레버 단위·캡틴 훅 첫 승선과 재탑승·롤러코스터 기어 연결 검사 통과. 실제 브라우저의 표시 프레임은 별도 확인하지 않았다.

## 새 레버 창과 손 이미지 적용
- `assets/captain-lever-frame-v2.png`를 공통 레버 창 배경으로 사용하고 기존 대사·레버를 유지했다. 창 크기와 글자 대비, 모바일 여백을 조정하고 공통 레버 CSS·JS와 이미지 주소에 버전을 지정했다. 정상 강제 이동은 1.6초, 오른쪽 도착 후 약 0.9초 더 표시한다. 움직임 줄이기의 정지 손 1.2초 유지는 그대로다. 이미지 파일은 변경하지 않았다.
- 실제 브라우저 캡처에서 새 창과 키퍼 손 이미지 로딩을 확인했다. 그 캡처에서 손이 오른쪽에 있을 때 손잡이가 왼쪽에 남는 배치 오류가 관찰되어 손잡이 위치를 직접 갱신하도록 추가 수정했다. 수정 후 자동 검사는 통과했지만, 마지막 수정에 대한 실제 브라우저 캡처는 다시 확인하지 못했으므로 접점·동시 이동은 미확정이다. 캡틴 화면 위주로 확인했으며 모바일 실기기 검증도 아직 없다.
- 변경: `coaster-lever.css`, `coaster-lever.js`, `index.html`. `verify-coaster-lever.cjs`, `verify-captain-lever.cjs`, `threads/verify-coaster-integration.cjs` 통과.

## 레일·손잡이 신규 일러스트 통합 준비
- 기존 STOP·GO PNG 표지는 앞선 요청에 따라 공통 레버에 적용했다. 데스크톱 및 390px 화면에서 두 표지 이미지의 로딩·가독성을 확인했고 공통 레버, 캡틴 훅, 롤러코스터 자동 검사는 통과했다. 실제 포인터 드래그 확인은 뷰포트 전환 직후 좌표가 맞지 않아 성공 여부를 확정하지 못했다.
- 신규 레일·표지 배경은 기존 트랙의 양끝과 일치하는 좌표계를 제공해야 한다. 분리된 손잡이는 시각 이미지와 포인터 입력 버튼을 분리하되 버튼의 충분한 조작 영역·슬라이더 접근성·방향키를 유지해야 한다. 키퍼 손과 손잡이는 동일한 0–100% 진행값과 동일한 전환 시간으로 움직이고, 시작·끝 및 좁은 화면에서 손가락과 손잡이의 접점을 확인한다.
- 안내 3초, 강제 개입, 움직임 줄이기, 취소·재입장·타이머 정리와 두 놀이기구의 기존 진행 경로는 보존한다. 이미지 실패 시 대체 표기와 캐시 버전을 유지한다. 새 에셋 전달 전에는 추가 코드 변경을 하지 않는다.
- 실기기 터치, 손과 손잡이의 강제 이동 중 접점은 신규 에셋을 반영한 뒤 브라우저에서 다시 확인해야 한다. 별도 요청 일치 검증은 HQ의 지정 스레드에서 수행한다.

## 새 일러스트 표시 문제 조사
- 사용자 제보: 새 레버 이미지가 제대로 표시되지 않고 키퍼가 사라짐. 레일·손잡이·손 이미지 파일의 존재와 CSS/JS 연결은 확인했고, 손 이미지는 역방향 안내 3초 후에만 표시되도록 되어 있다. 열린 오래된 탭은 변경 전 코드를 계속 사용할 수 있다.
- 이번 작업 환경에서는 앱 내 브라우저가 제공되지 않았고 로컬 미리보기 서버 연결도 거부되어 실제 게임 화면 재현, 이미지 로딩 및 위치 확인을 하지 못했다. 원인을 확인하지 못해 게임 코드는 바꾸지 않았다. 키퍼 월드 렌더러는 별도 오류 조사 범위로 건드리지 않았다.
- 기존 공통 레버·캡틴 훅·롤러코스터 모의 조작 자동 검사는 통과했으나 이미지 렌더링은 검사하지 않는다. 실제 브라우저에서 새로고침 후 레일, 손잡이와 왼쪽 시도→3초 후 손·접점을 확인하고 사용자의 키퍼 문제는 별도 오류 조사 결과와 함께 확인해야 한다. 독립 요청 일치 검증은 아직 필요하다.
