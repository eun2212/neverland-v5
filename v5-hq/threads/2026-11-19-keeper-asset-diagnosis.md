# 키퍼·레버 이미지 표시 조사 — 2026-11-19

- 현재 실제 소스 기준 공통 레버의 배경, 레일, 손잡이, STOP/GO 및 손 이미지 6개 파일이 모두 존재한다. index.html의 keeper-art 16개 원본 경로도 모두 존재한다. 파일 존재는 브라우저 전송·디코딩 성공을 뜻하지 않는다.
- 공통 레버는 배경·레일·손잡이를 CSS background로 사용하고, 표지와 손은 img를 사용한다. 표지/손 로드 실패 시 img를 제거해 대체 표시가 나타난다. CSS background는 요청 실패 시 이미지를 표시하지 않으며, 특히 손잡이는 새 배경 이미지 규칙이 이전 손잡이 그림을 덮어쓰므로 로드 실패 시 조작부가 보이지 않을 수 있다. 실제 요청 실패 여부는 미확인.
- JS/CSS와 이미지에 ?v=20261119 버전이 있다. 이미 로드된 이전 탭이 변경을 반영하지 않을 수 있으나 이번 증상의 원인으로 확인되지는 않았다. index.html의 script/link에 버전 여부는 HQ가 현행 배포 화면 기준 확인 필요.
- 키퍼의 게임 내 외형은 레버 손 PNG가 아니라 keeper-art의 포즈 이미지를 사용하는 독립 경로다. carnival-scene.js의 3D 키퍼는 keeperIntroduced 및 exploring이 참일 때 표시하고, 놀이기구 내부에서는 명시적으로 숨긴다(예외: passage). 스토리 입상은 story-core.js/showKeeperPose 및 story-3d.js의 syncKeeperPortrait3d가 별도 제어한다. 따라서 레버 손 에셋 연결만으로 게임 전체 키퍼가 지워졌다고 판단할 근거는 없다. 사라진 위치·조건을 특정해야 한다.
- 이전 세션의 앱 내 브라우저에서 WebGL 생성 실패가 3D 장면 초기화를 중단하는 오류가 확인된 바 있으나 현재 제보와 동일한 원인이라는 증거는 없다. 이번 스레드는 브라우저 목록이 비어 있고 iab 생성도 실패하여 실제 화면, 네트워크 응답과 콘솔은 확인하지 못했다.
- 권장 확인: 사용자가 보고 있는 동일 URL/탭에서 저장 데이터를 지우지 않고 새로고침한 다음, 캐시된 JS/CSS 버전·이미지 요청의 상태와 naturalWidth, 콘솔 오류, 키퍼가 사라진 장소/대사 여부를 확인한다. 정상 공원 보행에서 body.exploring, keeperIntroduced, 3D Sprite visible도 함께 확인한다. 게임 코드 수정 없음.

## 서버 재시작 후 긴급 진단
- HQ가 서버 종료를 관찰했고 재시작 후 게임·키퍼·레버 파일의 HTTP 200을 확인했다는 전달받았다. 서버 종료 시 이미 열린 게임이 새로 요청하는 이미지가 실패하여 키퍼와 새 이미지가 깨지는 현상을 설명할 수 있다. 서버가 왜 종료됐는지, 이것이 모든 증상의 유일한 원인인지는확인되지 않았다.
- preview-server.cjs는 URL의 쿼리를 pathname에서 분리하며 PNG는 image/png로 제공한다. 이미지 여섯 개와 키퍼 16포즈 파일은 디스크에 존재한다. 버전 쿼리가 JS/CSS와 새 이미지에 붙어 있다. 이 샌드박스는 127.0.0.1:8766 소켓 접근이 차단되어 HQ가 보고한 HTTP 200을 독립 재검증하지 못했다.
- 0x8007000E는 메모리 부족을 시사한다. 레버의 배경·레일·손잡이·표지 2개·손은 각각 약 157만 픽셀로, 디코딩 시 RGBA 기준 합계 약 36 MiB(복사본·GPU 텍스처·기존 게임 이미지 제외)가 될 수 있다. 이것이 앱 종료의 원인이라는 증거는 아직 없다. 성능 개선 시 원본 파일 보존과 실제 표시 크기에 맞춘 별도 최적화 에셋 및 시각 검증이 필요하다.
- verify-captain-lever.cjs, verify-coaster-lever.cjs, verify-full-story.cjs 통과. 모형 테스트여서 이미지 디코딩과 메모리 부족·실제 시각 표시를 확인하지 못한다.
- 앱 재실행/추가 탭 생성 없이 조사했다. 이번 요청에 대해 사용자 증상의 직접 원인으로 입증된 코드 결함은 발견하지 못했으므로 게임 코드를 수정하지 않았다. 현재 작업 스레드에 iab 연결이 없어 화면 재확인 불가.


## 대화 초상화 및 WebGL 추가 조사
- index.html의 keeper-art 16개 일반 포즈 및 keeper-melt.js가 계산한 최종 포즈 파일 모두 디스크에 존재한다. 대화 초상화는 story-core.js showKeeperPose와 story-3d.js syncKeeperPortrait3d에서 설정하며, 초기 상태에는 keeper-unseen으로 숨기고 키퍼가 말하면 해제한다. walking, cut, event-cutscene 등 일부 장면에서 CSS가 의도적으로 감춘다. 특정 대화에서 어떤 클래스·src·이미지 요청 결과가 적용됐는지 관찰하지 못해 초상화 소실의 원인을 확정하지 못했다. 서버가 꺼졌을 때 요청된 이미지가 실패한 가능성은 있으나 증거는 미확정.
- HQ에서 현재 탭에 WebGL context 생성 실패(GL_VENDOR/RENDERER Disabled)와 world.js 및 carnival-scene.js 초기화 실패를 확인했다. 코드 순서상 world.js가 실패하면 window.neverlandWorld가 정의되지 않고 story-3d.js의 world3d.connect와 sync3d의 world3d.state 접근도 실패할 수 있다. 이는 게임 시작·대화 전환을 방해하는 확정적인 의존성 경로다. 초상화 파일 요청 실패와의 동일 원인은 확인되지 않았다.
- 과거 같은 환경에서 첫 WebGL 요청부터 실패해 단순히 게임이 두 컨텍스트를 만들어 한도를 초과했다고 단정할 수 없었다. WebGL 런타임/브라우저 GPU 초기화 원인은 확인되지 않았다. 현재 브라우저 탭을 추가로 열거나 앱·사용자 탭을 재시작하지 않았다. 기존 탭의 이미지 요청 상태(naturalWidth와 오류), keeper-unseen/walking/cut/event-cutscene 클래스 및 GPU 진단을 기존 탭에서 확인해야 원인을 좁힐 수 있다. WebGL이 동작하는 환경에서 원본 3D 확인이 필요하다.
- 지도 폴백은 사용자 요청에 따라 다시 적용하지 않았다. 원인으로 입증된 대화 초상화 코드 결함을 찾지 못해 게임 코드는 수정하지 않았다.

## Codex 내 브라우저 WebGL 초기화 조사
- 관찰된 로그: 최초 world.js의 WebGL 요청이 실패하고 Three.js 생성 시 GL_VENDOR/GL_RENDERER Disabled, BindToCurrentSequence failed. 이후 story-3d.js에서 world3d.connect/state 접근이 실패한다. 이 오류는 레버 에셋·서버 MIME만의 문제로 설명되지 않는다.
- 두 컨텍스트: 보이지 않는 world-world 캔버스의 WebGL과 실제 화면용 Three.js WebGL을 각각 만든다. 컨텍스트·메모리 절약 대상으로는 명확하지만 이미 첫 요청부터 실패한 사례가 있어 이를 제거하면 현재 문제가 고쳐진다고 확정할 수 없다. 단순히 world.js 실패만 무시하면 실제 3D 렌더러도 실패하므로 게임을 정상 복구할 수 없다.
- 0x8007000E는 메모리 할당 실패를 뜻하는 단서이나 메모리 압박·GPU 프로세스 문제·드라이버 문제 중 어느 것이 근본 원인인지는 이 로그만으로 구분 불가. 타 탭이나 앱 종료·캐시 삭제·하드웨어 설정 변경 없이 진단했으며, 이 세션에는 iab 연결이 없어 재현 환경의 GPU 상태를 더 조회할 수 없었다.
- 실질적 조치: 기존 진행 저장 여부를 먼저 확인하고, 사용자가 허용한 시점에 Codex 앱을 정상 재시작해 기존 메모리/GPU 프로세스 상태를 정리한 후 동일 미리보기를 하나만 열어 확인한다. 다른 WebGL 지원 브라우저에서 같은 주소가 정상인지 비교하면 앱 환경과 시스템 공통 원인을 구분하는 데 도움이 된다. 저장 데이터 삭제는 불필요하다. 재시작이 원인을 해결한다고 보장하지 않는다.
- 최소 코드 개선 후보: 초기 컨텍스트 또는 Three.js 생성 실패 시 시작 버튼을 비활성화하고 WebGL 미지원/초기화 실패 안내 및 재시도 방법을 표시해 연쇄 TypeError와 무반응을 막는다. 이는 진단 안내이며 WebGL 복구가 아니다. 이후 별도 검증으로 보이지 않는 보조 컨텍스트 제거·컨텍스트 손실 이벤트 처리를 검토할 수 있다. 사용자가 되돌린 지도 폴백을 재적용하지 않았다. HQ 통합 전 제안 단계이며 게임 파일 수정 없음.
