# 롤러코스터 2D 출발 레버

- 요청: 기어 체결 뒤 독립 레버 화면. 오른쪽 끝에서 출발, 왼쪽 역조작 시 키퍼의 손이 오른쪽으로 밀고 출발. 최초 왼쪽 끝에서 왼쪽으로 끌어도 개입. 포인터/터치, 키보드, 취소, reduced motion 지원.
- 결과: `neverland-v4/coaster-lever.js`, `coaster-lever.css` 및 `verify-coaster-lever.cjs` 작성. `coaster.js`, `index.html`은 수정하지 않음. 현재 게임에는 미통합.
- HQ 통합: CSS와 JS를 로드하고 기어 체결 완료 시 기존 자동 출발을 보류한 뒤 `const lever = window.NEVERLAND_COASTER_LEVER.mount(container, { onStart({forced}) { /* 기존 출발 로직 */ }, onCancel() { /* 기존 닫기 또는 이전 화면 */ }, handImage: '에셋 경로' });` 호출. 종료/재시작 시 `lever.destroy()` 호출. 기본적으로 레버에 포커스하며 `focus:false`로 끌 수 있음. `reducedMotion`은 불리언 또는 함수로 선택 전달 가능. 외부에서 패널을 숨기거나 파괴할 때도 destroy 필요.
- 조작: 포인터/터치 드래그, 방향키 10%, Home/End, Escape 또는 돌아가기. 포인터의 최대 위치에서 왼쪽으로 3% 또는 3px 이상 이동하면 개입. 직접 끝까지 이동하면 즉시 출발, 개입 시 애니메이션 후 출발. 동작 줄이기에서는 애니메이션 없이 출발. 취소/파괴 시 대기 중 출발 취소.
- 이미지: `handImage`로 교체 가능. 미지정 또는 로드 실패 시 임시 손 표시. 전달되지 않은 참고 이미지와의 일치는 미확정.
- 검증: `node verify-coaster-lever.cjs` 통과(직접 출발, 초기/이동 후 역방향, 키보드, 동작 줄이기, 취소와 정리). `node --check coaster-lever.js` 통과. 브라우저 시각 및 실제 터치 검증, 게임 통합 검증은 아직 수행하지 않음.
- 통합 상태: HQ 대기.

## 캡틴 훅 첫 조작으로 이동 (2026-11-18)
- 롤러코스터는 세 기어 체결 후 즉시 출발하도록 복원했다. 캡틴 훅 첫 조작에 2D 레버를 연결했으며 이후 캡틴 훅 안전 구간 퍼즐은 유지한다.
- 오른쪽 GO 도달 시 자동 출발, 초기 왼쪽 또는 이동 후 역조작 시 키퍼 손과 글리치 후 강제 출발. 취소는 첫 승선 선택지로 복귀하고, 화면 교체·재시작 때 대기 중 연출을 정리한다. 첫 조작 직후 기존 대사 및 실제 첫 항해로 연결한다. 정지 고리는 레버와 별도임을 후속 대사에서 명확히 했다.
- `assets/captain-lever-panel.png`, `assets/keeper-captain-lever-hand.png` 연결. 배경은 CSS `--captain-lever-art`, 손은 모듈 `handImage` 옵션으로 교체 가능하다.
- 변경: `coaster.js`, `coaster-lever.js`, `coaster-lever.css`, `story-core.js`, `keeper-story.js`, `verify-full-story.cjs`. 전체 스토리 검사에 있던 원본 코드 바이트 동일성 검사는 이번에 의도적으로 첫 조작을 바꾸었으므로 레버 모듈 연결 검사로 교체했다.
- 검증: 레버 단위 검사 통과(직접 출발, 초기/후속 역방향, 키보드, 취소, reduced motion, 정리). 전체 스토리 551, 키퍼 스토리 716, 제작 도구 604개 검사 통과. 브라우저 제작 장면 이동으로 첫 조작 화면, 배경, 초기 왼쪽 키보드 조작 뒤 강제 출발 및 기존 대사 전환 확인. 실제 터치 및 키퍼 손 애니메이션의 프레임별 배치는 별도 실기기 검증하지 않았다.
- 통합 상태: 게임 통합본에 반영됨. 미리보기 `http://127.0.0.1:8766/`.

## 첫 승선 연결 추가 검증
- `neverland-v4/verify-captain-lever.cjs`를 추가했다. 실제 첫 승선 대화와 실제 레버 모듈을 같은 테스트 환경에 연결해 조작한다.
- 첫 승선에서 레버 열기, 취소 후 승선 선택지 복귀, 재입장 초기화, 오른쪽 드래그 및 End 직접 출발, 초기 왼쪽 드래그 및 방향키 강제 출발, 출발 대사 후 실제 첫 항해 시작을 확인했다. 강제 연출 중 취소 또는 새 게임을 시작하면 지연된 출발이 발생하지 않는 것도 확인했다.
- `node verify-captain-lever.cjs` 통과(기존 스토리 551개 검사 포함). 모의 입력 기반 자동 검증이며 실제 터치 기기 검증은 아니다. WebGL 초기화 코드는 변경하지 않았다.

## 시작 버튼 멈춤 독립 조사
- 앱 내 브라우저에서 시작 버튼 직후 제목창은 닫히나 대사가 시작되지 않는 현상을 재현했다. 당시 브라우저 오류는 `world.js`의 WebGL 초기화 실패, 이어진 `story-3d.js`의 `world3d` 접근 실패였고, 레버 화면에는 아직 도달하지 않았다. 레버 변경이 직접 원인이라는 증거는 찾지 못했다.
- 오류 조사 작업이 `world.js`에 대체 화면을 반영한 이후 새로고침하여 같은 브라우저에서 재검증했다. 시작 버튼 → 첫 대사 → 두 번째 대사 → 캡틴 훅 앞 이동 장면까지 정상 전환했다. 이 작업에서는 WebGL 초기화 파일을 수정하지 않았다.
- `node verify-captain-lever.cjs`(첫 승선 연결 및 기존 551개 검사)와 `node verify-dialogue-controls.cjs`(14개 검사) 통과. 초기 재현과 수정 후 확인은 앱 내 브라우저의 WebGL 불가 환경에서 이뤄졌다.

## 3D 공간 복원
- 사용자 요청에 따라 WebGL이 없을 때 표시하던 임시 2D 지도 대체 화면과 그에 연결된 비활성화 처리를 제거했다. 기존 3D 렌더링 경로와 캡틴 훅 레버 조작은 유지한다.
- `node verify-captain-lever.cjs` 통과. `verify-carnival-scene.cjs`는 3D 첫 프레임과 롤러코스터 검사를 통과했으나 뒤의 마스코트 이미지 로딩 검사에서 테스트 환경에 document가 없어 실패했다. 앱 내 브라우저는 WebGL을 사용할 수 없어 복원된 3D 화면을 이 환경에서 확인하지 못했다. 따라서 해당 브라우저의 시작 멈춤은 다시 발생할 수 있다.

## 롤러코스터 레버 상태 복원

- 변경: `coaster.js`, `coaster-lever.js`, `coaster-lever.css`, `story-core.js`, `keeper-story.js`, `verify-full-story.cjs`, `verify-captain-lever.cjs`, `threads/verify-coaster-integration.cjs`. WebGL 관련 파일은 건드리지 않았다.
- 검증: 롤러코스터 기어→레버, 취소·재입장, 직접/강제 출발 및 진행 중 닫기 통과. 캡틴 훅 기존 슬라이더와 출발 버튼 및 첫 항해 통과. 전체 스토리 551, 키퍼 716, 제작 도구 604개 검사 통과. 현재 열려 있던 브라우저는 이전 실행 상태이므로 이 변경의 시각적 재검증은 수행하지 않았다.
